Por que mais contexto

O bigrama parou em 2,454. Para fazer melhor, o modelo precisa olhar mais de uma letra para trás.

O conjunto inteiro tem 228.146 exemplos. Com 3 letras de contexto há mais de duas casas para cada exemplo: quase tudo fica zero.

Uma tabela trata cada contexto como uma ilha. "..a" e "..e" não compartilham nada, mesmo sendo situações parecidas: começo de nome, vogal.

A ideia da aula

Representar cada letra por um vetor aprendido. Letras que se comportam parecido ficam com vetores parecidos, e o que a rede aprende sobre uma vale um pouco para a outra. A arquitetura segue o artigo de Bengio et al. (2003) sobre modelos de linguagem neurais.

Bloco 2 de 5

A janela de contexto

O conjunto de treino muda de forma: agora a entrada são três letras.

Bloco 2 · Janela

Uma janela de três letras desliza pelo nome

block_size = 3   # quantas letras olhamos para prever a próxima

def build_dataset(words):
    X, Y = [], []
    for w in words:
        context = [0] * block_size     # começa com '...'
        for ch in w + '.':
            ix = stoi[ch]
            X.append(context)
            Y.append(ix)
            context = context[1:] + [ix]   # corta e anexa
    return torch.tensor(X), torch.tensor(Y)

Bloco 3 de 5

Embeddings

Uma tabela pequena que guarda um vetor por letra. A rede aprende os valores junto com o resto.

Bloco 3 · Embeddings

A tabela C: uma linha por letra

C = torch.randn((27, 2))   # 27 letras, 2 números cada

C[5]          # o vetor da letra 'e', shape (2,)
emb = C[X]    # indexa o tensor inteiro de uma vez
emb.shape     # (N, 3, 2)

Indexar C com o tensor X troca cada índice pelo seu vetor. Para X de shape (N, 3), o resultado é (N, 3, 2): N exemplos, 3 letras, 2 números por letra.

O mesmo truque da Aula 02

F.one_hot(5, 27).float() @ C dá exatamente C[5]. Ou seja, a tabela de embeddings é uma primeira camada linear sem viés, alimentada por one-hot. Indexar é só o jeito barato de fazer a mesma conta.

No modelo final, cada letra vira um vetor de 10 números em vez de 2: a tabela passa a ter shape (27, 10).

Bloco 3 · Embeddings

Juntar as três letras num vetor só: view

emb.shape                 # (32, 3, 2)

h_in = emb.view(-1, 6)    # (32, 6): as 3 letras lado a lado

# alternativa que funciona, mas copia memória:
torch.cat(torch.unbind(emb, 1), 1)

A camada escondida espera um vetor por exemplo. view(-1, 6) lê os mesmos números como 6 colunas por linha; o -1 deixa o PyTorch calcular o número de linhas.

Por que view é de graça

Um tensor é um bloco de memória contínuo mais uma "regra de leitura" (shape e strides). view só troca a regra; nenhum número é copiado. Já torch.cat cria um tensor novo.

Armadilha

O 6 é block_size × dimensão do embedding. Mudou um dos dois e esqueceu de mudar o número, o view quebra ou, pior, embaralha os exemplos. No modelo final o valor é 30 (3 × 10).

Bloco 3 · Embeddings

Depois do treino, as vogais se juntam

  • a, e, i, o, u ficam juntas à direita: para prever a próxima letra, elas se comportam de forma parecida.
  • q fica isolado: é quase sempre seguido de "u", um comportamento único.
  • O ponto também se afasta: marcar início e fim é um papel diferente de qualquer letra.

Com só 2 números por letra o modelo fica apertado: validação em 2,288. É um gargalo, e o Bloco 5 mostra o ganho de abrir para 10.

Bloco 4 · A rede

O forward em quatro linhas

g = torch.Generator().manual_seed(2147483647)
C  = torch.randn((27, 10), generator=g)
W1 = torch.randn((30, 200), generator=g)
b1 = torch.randn(200, generator=g)
W2 = torch.randn((200, 27), generator=g)
b2 = torch.randn(27, generator=g)
parameters = [C, W1, b1, W2, b2]

emb = C[Xtr[ix]]                         # (32, 3, 10)
h = torch.tanh(emb.view(-1, 30) @ W1 + b1)   # (32, 200)
logits = h @ W2 + b2                     # (32, 27)
loss = F.cross_entropy(logits, Ytr[ix])

emb.view(-1, 30) @ W1 tem shape (32, 200) e b1 tem (200,). O broadcasting estica b1 para todas as 32 linhas: cada neurônio soma o mesmo viés em todos os exemplos. Exatamente o que queremos.

tanh

A não linearidade da Aula 01. Sem ela, duas camadas lineares seguidas valeriam uma só, e a camada escondida não serviria para nada.

Bloco 4 · A rede

Use F.cross_entropy, não a conta à mão

# à mão (Aula 02):
counts = logits.exp()
prob = counts / counts.sum(1, keepdims=True)
loss = -prob[torch.arange(32), Y].log().mean()

# igual, e melhor:
loss = F.cross_entropy(logits, Y)
  • Mais eficiente: não cria os tensores intermediários.
  • Backward mais simples: o gradiente da combinação inteira tem fórmula fechada.
  • Numericamente estável: o motivo que mais importa.
O estouro do exp

Com logits como [−3, 0, 5, 100], exp(100) estoura o float32 e vira inf. Dividir inf por inf dá nan, e o treino morre.

A cross_entropy subtrai o maior logit antes do exp. A resposta não muda, porque a softmax dá o mesmo resultado se você somar a mesma constante a todos os logits; só que agora o maior expoente é 0.

Bloco 5 de 5

Treinar direito

Três técnicas que você vai usar em todo modelo daqui para frente: minibatch, varredura da taxa de aprendizado e a separação em treino, validação e teste.

Bloco 5 · Treino

Minibatch: 32 exemplos por passo

for i in range(200000):
    ix = torch.randint(0, Xtr.shape[0], (32,))   # minibatch

    emb = C[Xtr[ix]]
    h = torch.tanh(emb.view(-1, 30) @ W1 + b1)
    logits = h @ W2 + b2
    loss = F.cross_entropy(logits, Ytr[ix])

    for p in parameters:
        p.grad = None
    loss.backward()

    lr = 0.1 if i < 100000 else 0.01             # decaimento
    for p in parameters:
        p.data += -lr * p.grad

Calcular o gradiente com os 182 mil exemplos a cada passo é caro. Com 32 sorteados, o gradiente é uma aproximação, mas aponta para a direção certa na média.

A troca

É muito melhor dar muitos passos aproximados do que poucos passos exatos. Na minha reprodução em NumPy, os 200 mil passos levaram 27 s.

Efeito colateral: a loss de cada passo fica ruidosa. Para avaliar o modelo, calcule a loss no conjunto inteiro, como no slide de diagnóstico.

Bloco 5 · Treino

Achar a taxa de aprendizado em vez de chutar

lre = torch.linspace(-3, 0, 1000)
lrs = 10**lre          # de 0.001 a 1

for i in range(1000):

Mil passos, cada um com uma taxa maior que a anterior, em escala exponencial. A curva desce enquanto a taxa ajuda, chega a um vale e explode quando a taxa fica grande demais.

Leitura

Escolha uma taxa no vale, um pouco antes da subida: aqui, 0,1. Depois, no fim do treino, reduza 10 vezes (0,01) para refinar.

Bloco 5 · Treino

200 mil passos, com o decaimento visível

A loss inicial é enorme, 26,6, muito acima dos 3,30 de um chute uniforme. Os pesos aleatórios fazem a rede dar probabilidade quase zero para a letra certa, com muita confiança.

Em 100 mil passos a taxa cai de 0,1 para 0,01 e a curva dá um degrau para baixo: com passos menores o modelo para de pular em volta do vale.

Esse começo ruim tem conserto, e é o assunto da parte 3: inicializar os pesos com a escala certa.

Loss média sobre o conjunto inteiro, não o minibatch. A reprodução usou outra semente, por isso os números diferem um pouco.

Como ler

Treino ≈ validação: o modelo não está decorando o conjunto. Se estiver ruim, é underfitting e o remédio é um modelo maior: mais neurônios, embedding maior, mais contexto.

Treino bem abaixo da validação: overfitting. O modelo decorou; o remédio é mais dados, regularização ou um modelo menor.

Aqui a diferença é de 0,04: ainda há espaço para aumentar o modelo antes de começar a decorar.

Bloco 5 · Treino

Três aulas, uma escada de losses

Abrir o embedding de 2 para 10 dimensões e a camada de 100 para 200 neurônios levou a validação de 2,288 para 2,155.

O processo

Mudar um hiperparâmetro, treinar, medir na validação, anotar. Esse ciclo é o trabalho do dia a dia em ML, e o conjunto de validação é o que o torna honesto.

Fechamento

A aula em seis linhas

  • Contar não escala com mais contexto; vetores aprendidos generalizam entre contextos parecidos.
  • Janela deslizante: block_size letras de entrada, a próxima de saída. Pontos preenchem o começo.
  • Embeddings: C[X] é uma camada linear sobre one-hot, feita por indexação. view concatena sem copiar.
  • Rede: tanh na camada escondida, logits na saída e F.cross_entropy, que é mais rápida e estável.
  • Treino: minibatch de 32, taxa achada por varredura (0,1) e decaimento no fim (0,01).
  • Três conjuntos: treino ajusta, validação escolhe, teste mede uma vez. Treino ≈ validação → aumente o modelo.

1Por que a tabela de contagem não funciona com 3 letras de contexto?
São 19.683 contextos × 27 = 531.441 contagens para 228 mil exemplos: quase tudo fica zero. E cada contexto é uma ilha: nada aprendido sobre "..a" ajuda em "..e". Os embeddings compartilham informação entre contextos parecidos.
2Com X de shape (32, 3) e C de (27, 10), qual é o shape de C[X]? E depois de .view(-1, 30)?
(32, 3, 10), e depois (32, 30): os três vetores de cada exemplo lado a lado, sem copiar memória.
3Por que usar F.cross_entropy em vez de exp, normalizar e log à mão?
É mais eficiente, tem backward mais simples e é estável: subtrai o maior logit antes do exp, o que evita o inf e o nan com logits grandes, sem mudar o resultado.

4Se o gradiente de um minibatch de 32 é só uma aproximação, por que funciona?
Na média ele aponta na direção certa. Muitos passos baratos e aproximados chegam mais longe do que poucos passos exatos e caros, no mesmo tempo.
5Como a varredura de taxa de aprendizado leva a 0,1?
