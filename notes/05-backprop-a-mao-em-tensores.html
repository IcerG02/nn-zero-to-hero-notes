Bloco 0

Por que fazer à mão

O PyTorch calcula tudo sozinho. Ainda assim, quem não entende o que ele calcula fica sem ação quando algo dá errado.

Bloco 0 · Motivação

O backprop é uma abstração que vaza

Karpathy defende isso desde um ensaio de 2016, "Yes you should understand backprop": o .backward() funciona até deixar de funcionar, e aí o problema é do seu código, não da biblioteca.

  • Gradientes que somem numa tanh saturada (Aula 04).
  • Neurônios mortos que nunca recebem gradiente.
  • Cortar gradientes (clipping) no lugar errado e perder o sinal.
  • Uma operação que quebra o grafo sem dar erro.
A ponte com a Aula 01

No micrograd o backprop era com escalares: cada nó um número. Aqui é a mesma regra da cadeia, mas cada nó é um tensor, e o trabalho passa a ser acertar shapes, somas e broadcasts.

Rede do exercício: embedding 10, camada de 64 neurônios, BatchNorm, tanh e saída de 27. São 4.137 parâmetros, inicializados de propósito de forma "estranha" para que um erro de backward não fique escondido atrás de zeros.

Exercício 1

Tudo, passo a passo

O forward é quebrado em pedaços pequenos, e cada pedaço ganha seu gradiente.

Exercício 1 · Passo a passo

O forward picado em 20 pedaços

emb = C[Xb]                                  # embedding
embcat = emb.view(emb.shape[0], -1)
hprebn = embcat @ W1 + b1                    # linear 1
bnmeani = 1/n*hprebn.sum(0, keepdim=True)    # batchnorm
bndiff = hprebn - bnmeani
bndiff2 = bndiff**2
bnvar = 1/(n-1)*(bndiff2).sum(0, keepdim=True)
bnvar_inv = (bnvar + 1e-5)**-0.5
bnraw = bndiff * bnvar_inv
hpreact = bngain * bnraw + bnbias
h = torch.tanh(hpreact)                      # não linearidade
logits = h @ W2 + b2                         # linear 2
logit_maxes = logits.max(1, keepdim=True).values   # cross-entropy
norm_logits = logits - logit_maxes
counts = norm_logits.exp()
counts_sum = counts.sum(1, keepdims=True)
counts_sum_inv = counts_sum**-1
probs = counts * counts_sum_inv
logprobs = probs.log()
loss = -logprobs[range(n), Yb].mean()

O exercício é andar de baixo para cima e escrever dlogprobs, dprobs, dcounts_sum_inv… até dC. Cada linha usa só a derivada local daquela operação e o gradiente que já chegou.

Regra de ouro

O gradiente de um tensor tem exatamente o mesmo shape que o tensor. Se o seu dX tem shape diferente de X, está errado.

Exercício 1 · Passo a passo

O gradiente da multiplicação de matrizes sai dos shapes

logits = h @ W2 + b2       # (32,64) @ (64,27) + (27,)

dh  = dlogits @ W2.T       # (32,27) @ (27,64) -> (32,64)
dW2 = h.T @ dlogits        # (64,32) @ (32,27) -> (64,27)
db2 = dlogits.sum(0)       # (32,27) -> (27,)

Você não precisa decorar. Pergunte: que produto dos tensores disponíveis tem o shape do gradiente que eu quero? Só existe um jeito de chegar a (64, 27) combinando h (32,64) e dlogits (32,27): h.T @ dlogits.

Por que o viés é somado

b2 tem shape (27,) e foi esticado (broadcast) para as 32 linhas. Ele foi usado 32 vezes, então os 32 gradientes se somam: dlogits.sum(0). É o += da Aula 01 em forma de tensor.

Para conferir de cabeça: escreva a conta para um único elemento, por exemplo logits[0,0] = Σ h[0,k]·W2[k,0], e derive.

Exercício 1 · Passo a passo

Soma e broadcast são duais

No forwardNo backward
soma ao longo de um eixobroadcast do gradiente de volta
broadcast de um tensorsoma dos gradientes
 
# forward: soma -> backward: broadcast
counts_sum = counts.sum(1, keepdims=True)    # (32,27) -> (32,1)
dcounts += torch.ones_like(counts) * dcounts_sum

# forward: broadcast -> backward: soma
probs = counts * counts_sum_inv              # (32,1) esticado
dcounts_sum_inv = (counts * dprobs).sum(1, keepdim=True)
Variáveis usadas duas vezes

counts aparece em counts_sum e em probs. O gradiente chega pelos dois caminhos e precisa ser somado: dcounts = ... e depois dcounts += .... Esquecer o segundo é o bug do = da Aula 01.

O max

logit_maxes manda o gradiente só para a posição do máximo de cada linha (one_hot do argmax). Como subtrair o máximo não muda a loss, esse gradiente deve dar praticamente zero.

Exercício 1 · Passo a passo

O embedding: o gradiente volta para as linhas usadas

demb = dembcat.view(emb.shape)       # (32,30) -> (32,3,10)
dC = torch.zeros_like(C)             # (27,10)
for k in range(Xb.shape[0]):
    for j in range(Xb.shape[1]):
        ix = Xb[k, j]
        dC[ix] += demb[k, j]         # += : letras repetidas acumulam

# versão vetorizada:
# dC.index_add_(0, Xb.view(-1), demb.view(-1, 10))

No forward, C[Xb] copia linhas de C. No backward, o gradiente de cada cópia volta para a linha de onde veio.

Como a mesma letra aparece muitas vezes no batch (o ponto aparece em quase todo contexto inicial), o += é obrigatório.

view é de graça nos dois sentidos

Se o forward fez view, o backward só desfaz o view. Nenhum número muda, só a forma de ler.

Exercício 1 · Passo a passo

Conferir: o seu gradiente contra o do PyTorch

def cmp(s, dt, t):
    ex = torch.all(dt == t.grad).item()          # bit a bit igual?
    app = torch.allclose(dt, t.grad)             # igual com tolerância?
    maxdiff = (dt - t.grad).abs().max().item()
    print(f'{s:15s} | exact: {ex} | approximate: {app} | maxdiff: {maxdiff}')

No notebook, todos os 26 tensores dão exact: True: o backward manual bate bit a bit com o do PyTorch.

ParâmetroErro relativo máx.

Minha conferência independente: reimplementei o backward em NumPy (float64) e comparei com diferenças finitas em 6 posições aleatórias de cada parâmetro. Erros entre 10⁻¹⁰ e 10⁻⁶ = gradiente certo.

Exercício 2

Cross-entropy de uma vez

Oito linhas de backward colapsam numa fórmula de três linhas.

Exercício 2 · Cross-entropy

O gradiente dos logits é softmax menos one-hot

dlogits = F.softmax(logits, 1)
dlogits[range(n), Yb] -= 1
dlogits /= n

Para um exemplo, com pᵢ = softmax: ∂loss/∂logitᵢ = pᵢ − 1 se i é a letra certa, e pᵢ caso contrário. A divisão por n vem da média do batch.

A intuição: um cabo de guerra

Cada letra errada é empurrada para baixo na proporção da probabilidade que recebeu. A letra certa é puxada para cima com força 1 − p. Cada linha soma zero: as forças se equilibram.

Exercício 3

BatchNorm de uma vez

A parte mais difícil da aula: a derivada da BN em relação à entrada, simplificada à mão.

Exercício 3 · BatchNorm

Uma linha no lugar de nove

dhprebn = bngain*bnvar_inv/n * (n*dhpreact - dhpreact.sum(0) - n/(n-1)*bnraw*(dhpreact*bnraw).sum(0))

Cada entrada xᵢ influencia a saída por três caminhos: diretamente, pela média do batch e pela variância do batch. Os três termos do parêntese são exatamente esses três caminhos.

  • n·dhpreact: o caminho direto.
  • − Σ dhpreact: o caminho pela média.
  • − n/(n−1)·bnraw·Σ(dhpreact·bnraw): o caminho pela variância.
Conferido

No notebook, a diferença para o backward passo a passo foi 9·10⁻¹⁰ (float32). Na minha reprodução em float64, 2·10⁻¹⁸.

n − 1

A variância usa a correção de Bessel (dividir por n − 1), e é daí que vem o n/(n−1). Karpathy chama atenção para usar a mesma convenção no treino e na inferência.

Exercício 4

Treinar sem autograd

Juntar os pedaços simplificados e treinar a rede inteira com o seu backward.

Exercício 4 · Sem autograd

O backward inteiro cabe numa tela

dlogits = F.softmax(logits, 1)          # cross-entropy
dlogits[range(n), Yb] -= 1
dlogits /= n
dh  = dlogits @ W2.T                     # linear 2
dW2 = h.T @ dlogits
db2 = dlogits.sum(0)
dhpreact = (1.0 - h**2) * dh             # tanh
dbngain = (bnraw * dhpreact).sum(0, keepdim=True)
dbnbias = dhpreact.sum(0, keepdim=True)
dhprebn = bngain*bnvar_inv/n * (n*dhpreact - dhpreact.sum(0)
          - n/(n-1)*bnraw*(dhpreact*bnraw).sum(0))   # batchnorm
dembcat = dhprebn @ W1.T                 # linear 1
dW1 = embcat.T @ dhprebn
db1 = dhprebn.sum(0)
demb = dembcat.view(emb.shape)           # embedding
dC = torch.zeros_like(C)
dC.index_add_(0, Xb.view(-1), demb.view(-1, n_embd))

for p, grad in zip(parameters, grads):
    p.data += -lr * grad                 # sem loss.backward()

O loop roda dentro de with torch.no_grad():: o PyTorch nem constrói o grafo, porque ninguém vai chamar backward().

Fechamento

A aula em seis linhas

  • O gradiente tem o mesmo shape do tensor. Use os shapes para descobrir a conta.
  • Matmul: dA = dOut @ B.T, dB = A.T @ dOut. Viés esticado → gradiente somado.
  • Soma ↔ broadcast: o que somou no forward vira broadcast no backward, e vice-versa.
  • Variável usada duas vezes recebe gradiente dos dois caminhos: +=.
  • Cross-entropy: dlogits = (softmax − one-hot) / n; cada linha soma zero.
  • BatchNorm: três caminhos (direto, média, variância), uma linha. Confira sempre com cmp ou diferenças finitas.
Pare e responda · 1 de 2

Responda antes de clicar

1Em out = A @ B, com A (32, 64) e B (64, 27), como se calcula dB?
A.T @ dout: (64, 32) @ (32, 27) = (64, 27), o shape de B.
2Por que db2 = dlogits.sum(0)?
O viés (27,) foi esticado para as 32 linhas no forward. Usado 32 vezes, ele recebe a soma dos 32 gradientes.
3Quanto vale a soma de uma linha de dlogits? Por quê?
Zero. É softmax (soma 1) menos one-hot (soma 1). Empurrar as erradas para baixo e puxar a certa para cima se equilibram.
Pare e responda · 2 de 2

Responda antes de clicar

4Por que o gradiente de logit_maxes deve sair praticamente zero?
Subtrair o máximo de todos os logits não muda a softmax, então não muda a loss. A loss não depende dele.
5Por que dC[ix] += demb[k, j] e não =?
A mesma letra aparece em várias posições do batch. Cada uso manda um gradiente para a mesma linha de C, e eles precisam ser somados.
6Quais são os três caminhos pelos quais uma entrada da BatchNorm afeta a saída?
Diretamente (o próprio valor), pela média do batch e pela variância do batch. Cada um vira um termo da fórmula simplificada.
