Bloco 1 · Dados

Um pedaço de 9 caracteres são 8 exemplos

def get_batch(split):
    data = train_data if split == 'train' else val_data
    ix = torch.randint(len(data) - block_size, (batch_size,))
    x = torch.stack([data[i:i+block_size] for i in ix])
    y = torch.stack([data[i+1:i+block_size+1] for i in ix])
    return x, y        # (B, T) e (B, T)

contexto [18, 47, 56]            → 57

contexto [18, 47, 56, 57, 58, 1, 15, 47] → 58

y é x deslocado uma posição. Assim, cada posição t do bloco é um exemplo: prever o próximo caractere vendo do 1º até o t-ésimo.

Por que treinar todos os tamanhos de contexto

O modelo aprende a prever a partir de 1 caractere até block_size caracteres. Na geração, ele começa com um contexto de tamanho 1 e vai crescendo.

Dimensões que voltam o tempo todo: B (batch), T (tempo, posição na sequência) e C (canais, o tamanho do vetor).

Bloco 1 · Dados

O bigrama da Aula 02, agora como nn.Module

class BigramLanguageModel(nn.Module):
    def __init__(self, vocab_size):
        super().__init__()
        self.token_embedding_table = nn.Embedding(vocab_size, vocab_size)

    def forward(self, idx, targets=None):
        logits = self.token_embedding_table(idx)   # (B, T, C)
        if targets is None:
            return logits, None
        B, T, C = logits.shape
        loss = F.cross_entropy(logits.view(B*T, C), targets.view(B*T))
        return logits, loss

O embedding 65 × 65 é a tabela da Aula 02: cada caractere lê direto os logits do próximo. A loss inicial foi 4,88, perto de −ln(1/65) ≈ 4,17.

O view antes da cross_entropy

F.cross_entropy espera (N, C). Com logits (B, T, C), é preciso juntar B e T numa dimensão só.

AdamW substitui o SGD manual: ajusta o passo de cada parâmetro e é o otimizador padrão para Transformers.

O truque da média

Para os caracteres "conversarem", cada posição precisa juntar informação das anteriores, e nunca das futuras.

Bloco 2 · Média

Uma matriz triangular faz a média do passado

a = torch.tril(torch.ones(3, 3))
a = a / torch.sum(a, 1, keepdim=True)
c = a @ b
a = [[1.00, 0.00, 0.00]     b = [[2, 7]     c = [[2.00, 7.00]
     [0.50, 0.50, 0.00]          [6, 4]          [4.00, 5.50]
     [0.33, 0.33, 0.33]]         [6, 5]]         [4.67, 5.33]]

Linha t de a tem pesos iguais nas posições 0…t e zero no futuro. Multiplicar por b dá, em cada linha, a média de tudo que veio até ali.

A ideia que vira atenção

Uma multiplicação de matrizes é uma soma ponderada. Se os pesos deixarem de ser fixos e passarem a depender dos dados, temos self-attention.

Bloco 2 · Média

Do loop à softmax mascarada

# versão 1: loop
for t in range(T):
    xbow[b, t] = torch.mean(x[b, :t+1], 0)

# versão 2: matriz de pesos
wei = torch.tril(torch.ones(T, T))
wei = wei / wei.sum(1, keepdim=True)
xbow2 = wei @ x            # (T,T) @ (B,T,C) -> (B,T,C)

# versão 3: softmax
tril = torch.tril(torch.ones(T, T))
wei = torch.zeros((T, T))
wei = wei.masked_fill(tril == 0, float('-inf'))
wei = F.softmax(wei, dim=-1)
xbow3 = wei @ x            # allclose(xbow, xbow3) -> True

A versão 3 é a que importa. wei começa em zero: afinidade igual com todo mundo. Onde é futuro vira −∞, e a softmax transforma −∞ em peso 0.

Leia assim

wei = afinidades entre posições. masked_fill = proibir olhar o futuro. softmax = transformar afinidades em pesos que somam 1.

O @ de (T, T) com (B, T, C) faz broadcast no batch: a mesma matriz de pesos para cada exemplo.

Self-attention

Agora as afinidades deixam de ser zero e passam a ser calculadas a partir de cada caractere.

Bloco 3 · Atenção

Uma cabeça de atenção

head_size = 16
key   = nn.Linear(C, head_size, bias=False)
query = nn.Linear(C, head_size, bias=False)
value = nn.Linear(C, head_size, bias=False)

k = key(x)      # (B, T, 16)
q = query(x)    # (B, T, 16)
wei = q @ k.transpose(-2, -1) * head_size**-0.5   # (B, T, T)

tril = torch.tril(torch.ones(T, T))
wei = wei.masked_fill(tril == 0, float('-inf'))
wei = F.softmax(wei, dim=-1)

v = value(x)    # (B, T, 16)
out = wei @ v   # (B, T, 16)
  • query: o que esta posição está procurando.
  • key: o que esta posição tem a oferecer.
  • value: o que ela comunica se for escolhida.

A afinidade entre duas posições é o produto escalar da query de uma com a key da outra. Query e key alinhadas = peso alto.

Por que o value

Separar "como sou encontrado" (key) de "o que entrego" (value) dá à cabeça mais liberdade do que fazer a média do próprio x.

Bloco 3 · Atenção

Pesos que dependem dos dados

Saída real do notebook: wei[0] de uma cabeça ainda não treinada, com T = 8. Cada linha é uma posição olhando para trás; cada linha soma 1.

Diferente da média uniforme, os pesos não são iguais: na linha 4, 0,79 do peso vai para uma única posição; na linha 7, ele se espalha por várias.

Tudo acima da diagonal é zero

É a máscara triangular: nenhuma posição vê o futuro. Isso é o que faz o modelo poder gerar texto um caractere de cada vez.

Bloco 3 · Atenção

Por que dividir por √head_size

Com q e k de variância 1, o produto escalar soma 16 termos e tem variância perto de 16. Na minha simulação: sem a escala e com ela.

Variância alta deixa a softmax "pontuda": ela converge para um one-hot e cada posição passa a olhar uma única outra. No começo do treino, isso trava o aprendizado.

Atenção "escalada"

* head_size**-0.5 mantém a variância em 1 e a softmax difusa. É o "scaled" de scaled dot-product attention.

Bloco 3 · Atenção

As notas do Karpathy sobre atenção

  • É um mecanismo de comunicação. Nós de um grafo dirigido que olham uns para os outros e agregam informação com pesos que dependem dos dados.
  • Não tem noção de espaço. Atenção age sobre um conjunto de vetores. Por isso é preciso somar um embedding de posição.
  • Exemplos do batch não conversam. Cada sequência é processada de forma independente.
  • Decoder vs encoder. Com a máscara triangular, é um bloco de decoder (gera texto). Sem a máscara, todas as posições se veem: encoder.
  • Self vs cross. Self-attention: queries, keys e values vêm do mesmo x. Cross-attention: keys e values vêm de outra fonte, como um encoder na tradução.
  • Escalada. Divide por √head_size para a softmax não saturar.
Bloco 4 de 5

O bloco Transformer

Atenção sozinha comunica. Falta computar, e falta fazer uma rede profunda treinar.

Bloco 4 · Bloco

Comunicação seguida de computação

class Block(nn.Module):
    def __init__(self, n_embd, n_head):
        super().__init__()
        head_size = n_embd // n_head
        self.sa = MultiHeadAttention(n_head, head_size)
        self.ffwd = FeedFoward(n_embd)       # Linear(C, 4C), ReLU, Linear(4C, C)
        self.ln1 = nn.LayerNorm(n_embd)
        self.ln2 = nn.LayerNorm(n_embd)

    def forward(self, x):
        x = x + self.sa(self.ln1(x))         # comunicação
        x = x + self.ffwd(self.ln2(x))       # computação
        return x
  • Multi-head: 4 cabeças de 16 em paralelo, concatenadas em 64. Cada uma pode buscar um tipo de relação.
  • Feed-forward: cada posição "pensa" sozinha sobre o que recebeu, com uma camada 4× mais larga.
  • Resíduo (x = x + ...): um caminho direto por onde o gradiente passa sem obstáculo. É o que permite empilhar muitos blocos.
  • LayerNorm antes de cada sub-bloco (pre-norm), como nos Transformers modernos.

Por que LayerNorm aqui

Ela não depende do batch: não acopla exemplos, não precisa de running stats e funciona igual no treino e na geração. Toda a dor de cabeça da BN da Aula 04 some.

Pare e responda · 1 de 2

Responda antes de clicar

1Por que um bloco de 9 caracteres gera 8 exemplos de treino?
Cada posição t prevê o próximo caractere usando os caracteres de 1 a t. Com 8 entradas e 8 alvos deslocados, são 8 previsões com contextos de tamanho 1 a 8.
2O que faz masked_fill(tril == 0, float('-inf')) antes da softmax?
Põe −∞ nas posições futuras. A softmax transforma −∞ em peso zero, e nenhuma posição olha para a frente.
3Qual o papel de query, key e value?
A query diz o que a posição procura, a key diz o que cada posição oferece, e o produto das duas dá a afinidade. O value é o que é efetivamente somado com esses pesos.
Pare e responda · 2 de 2

Responda antes de clicar

4Por que dividir q @ k.T por √head_size?
Sem isso, a variância das afinidades cresce com head_size, a softmax fica pontuda (quase one-hot) e cada posição olha só uma outra. A divisão mantém a variância perto de 1.
5Para que servem as conexões residuais x = x + f(x)?
Criam um caminho direto para o gradiente: a soma distribui o gradiente sem alterá-lo (Aula 01). Assim, redes com muitos blocos continuam treináveis.
6Qual a diferença entre LayerNorm e BatchNorm?
A BN normaliza cada neurônio ao longo do batch; a LN normaliza cada exemplo ao longo dos neurônios. A LN não depende do batch e não precisa de running stats.
