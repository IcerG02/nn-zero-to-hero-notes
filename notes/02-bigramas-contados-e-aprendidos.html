Bloco 1 de 5

O problema e os dados

Um modelo de linguagem em miniatura: em vez de palavras, letras; em vez de textos, nomes.

Bloco 1 · Dados

Dada uma letra, qual vem depois?

words = open('names.txt', 'r').read().splitlines()

len(words)                      # 32033
min(len(w) for w in words)      # 2
max(len(w) for w in words)      # 15

Um bigrama é um par de caracteres vizinhos. O modelo de bigramas olha só a última letra para prever a próxima. É o modelo de linguagem mais simples que existe e serve de linha de base para tudo que vem depois.

Cada nome vira vários exemplos de treino. "emma", com marcadores de início e fim:

.eemmmmaa.

Cinco exemplos de um nome só: começar com e, e seguido de m, m seguido de m, m seguido de a, e a terminar o nome.

Os números

32.033 nomes geram 228.146 bigramas. Esse é o tamanho do conjunto de treino.

Bloco 1 · Dados

Um único token para começo e fim

chars = sorted(list(set(''.join(words))))
stoi = {s:i+1 for i,s in enumerate(chars)}
stoi['.'] = 0                    # o marcador fica no índice 0
itos = {i:s for s,i in stoi.items()}

stoi = string → índice, itos = índice → string. As 26 letras ficam de 1 a 26.

A primeira versão usava dois marcadores, <S> e <E>. O problema: nada vem antes de <S> e nada vem depois de <E>, então uma linha e uma coluna da matriz ficam sempre vazias.

Com um só marcador, o ., ele faz os dois papéis: como letra anterior significa "início do nome"; como próxima letra significa "fim do nome".

Resultado

27 símbolos (26 letras + o ponto) e uma matriz 27 × 27 sem desperdício.

Bloco 2 de 5

Contar bigramas

O modelo inteiro cabe numa tabela: quantas vezes cada letra veio depois de cada letra.

Bloco 2 · Contagem

Contar é o treino inteiro

N = torch.zeros((27, 27), dtype=torch.int32)

for w in words:
    chs = ['.'] + list(w) + ['.']
    for ch1, ch2 in zip(chs, chs[1:]):
        ix1 = stoi[ch1]
        ix2 = stoi[ch2]
        N[ix1, ix2] += 1

N[i, j] guarda quantas vezes o caractere j apareceu logo depois do i. A linha é "onde estou", a coluna é "para onde vou".

zip(chs, chs[1:]) é o truque para andar de dois em dois: junta cada caractere com o seguinte.

Repare

Não há gradiente, otimizador nem época. Um passe pelos dados e o modelo está pronto. É por isso que ele é a linha de base perfeita: rápido e ótimo para o que se propõe.

Atenção para depois

102 das 729 combinações nunca aparecem. Para o modelo, elas são impossíveis. Guarde isso: no Bloco 4 esse zero vira uma loss infinita.

Bloco 2 · Contagem

A linha 0 diz como os nomes começam

p = N[0].float()      # contagens depois do '.'
p = p / p.sum()       # vira probabilidade
# p[1] (letra 'a') = 0.1377

Normalizar uma linha da matriz transforma contagens em uma distribuição de probabilidade: 27 números entre 0 e 1 que somam 1.

A linha 0 é a distribuição da primeira letra. A linha de "a" é a distribuição do que vem depois de "a", e assim por diante.

Bloco 3 de 5

Gerar nomes

Com as probabilidades na mão, gerar um nome é sortear uma letra de cada vez até sair o ponto.

Bloco 3 · Amostragem

Sortear com pesos: torch.multinomial

g = torch.Generator().manual_seed(2147483647)

ix = torch.multinomial(p, num_samples=1,
                       replacement=True,
                       generator=g).item()
itos[ix]     # 'm'

multinomial sorteia índices respeitando as probabilidades: se p dá 13,8% para "a", em cada sorteio "a" tem 13,8% de chance de sair.

O Generator com semente fixa faz o sorteio sempre dar o mesmo resultado. É assim que dá para comparar o seu código com o do vídeo, linha por linha.

Reprodutibilidade

Semente fixa não é detalhe: sem ela, nenhum experimento seu é comparável com o anterior.

Bloco 3 · Amostragem

Normalizar todas as linhas de uma vez

P = (N+1).float()
P /= P.sum(1, keepdims=True)

# P.sum(1, keepdims=True).shape -> (27, 1)
# P.sum(1).shape                -> (27,)

Em vez de normalizar linha por linha dentro do loop, a matriz P é normalizada uma vez só. sum(1) soma ao longo das colunas e dá o total de cada linha.

O +1 é a suavização, explicada no Bloco 4.

A armadilha silenciosa

Com keepdims=True a soma tem shape (27, 1) e é esticada para a direita: cada linha é dividida pelo próprio total. Certo.

Sem keepdims, o shape é (27,), e o broadcasting o trata como (1, 27): divide cada coluna. Não dá erro nenhum. As linhas simplesmente deixam de somar 1 e o modelo sai errado.

Hábito

Depois de normalizar, confira: P[0].sum() tem que dar 1.

Bloco 3 · Amostragem

Uma letra de cada vez, até sair o ponto

g = torch.Generator().manual_seed(2147483647)

for i in range(5):
    out = []
    ix = 0                     # começa no '.'
    while True:
        p = P[ix]              # linha da letra atual
        ix = torch.multinomial(p, num_samples=1,
             replacement=True, generator=g).item()
        out.append(itos[ix])
        if ix == 0:            # sorteou o '.': fim
            break
    print(''.join(out))

Bloco 4 de 5

Medir a qualidade

"Os nomes parecem ruins" não é métrica. Precisamos de um número que diga o quanto o modelo é bom, e que dê para otimizar.

Bloco 4 · Qualidade

Da likelihood à NLL média

Likelihood: a probabilidade que o modelo dá para os dados reais. É o produto das probabilidades de cada bigrama. Quanto maior, melhor.

O problema: multiplicar 228 mil números menores que 1 dá um valor tão pequeno que o computador arredonda para zero.

Por isso o log

log(a·b·c) = log a + log b + log c. O produto vira soma, e o log é crescente: maximizar um é maximizar o outro.

maximizar a likelihood
⇔ maximizar a log-likelihood
⇔ minimizar a negative log-likelihood
⇔ minimizar a NLL média ← a loss 
log_likelihood += torch.log(P[ix1, ix2])
nll = -log_likelihood
loss = nll / n       # média por bigrama

Calculei sobre os 228.146 bigramas do conjunto. Com a suavização +1, a NLL média sobe um tiquinho, para 2,4546: o preço de reservar probabilidade para pares nunca vistos.

Por que 2,454 é o piso

Para bigramas, contar e normalizar é a resposta ótima nos dados de treino. Nenhum modelo que olhe só uma letra vai fazer melhor que isso. Guarde o número: a rede do Bloco 5 vai tentar chegar nele.

Valores de −log por par; omiti os pares intermediários.

"jq" nunca aparece no conjunto. Sem suavização, sua probabilidade é 0, e −log 0 = ∞: um único par desconhecido torna a loss do nome inteiro infinita.

Suavização

N + 1 finge que cada par apareceu uma vez a mais. Nada fica com probabilidade zero, e "jq" vira só muito improvável. Quanto maior o número somado, mais o modelo se aproxima do uniforme.

Bloco 5 de 5

A mesma coisa como rede neural

Em vez de contar, aprender os números por gradiente. O resultado é quase o mesmo, mas o caminho é o que escala para modelos maiores.

Bloco 5 · Rede neural

Reescrever como entrada e rótulo

xs, ys = [], []
for w in words:
    chs = ['.'] + list(w) + ['.']
    for ch1, ch2 in zip(chs, chs[1:]):
        xs.append(stoi[ch1])     # entrada
        ys.append(stoi[ch2])     # rótulo
xs = torch.tensor(xs)
ys = torch.tensor(ys)            # 228146 exemplos

Cada bigrama vira um exemplo de treino: a primeira letra é a entrada, a segunda é o rótulo que a rede deve prever.

"emma"
xs = [ 0, 5, 13, 13, 1]
ys = [ 5, 13, 13, 1, 0]

0 é o ponto, 5 é "e", 13 é "m", 1 é "a".

Bloco 5 · Rede neural

One-hot: um índice vira um vetor

import torch.nn.functional as F

xenc = F.one_hot(xs, num_classes=27).float()
xenc.shape    # (5, 27) para "emma"

Não faz sentido multiplicar pesos pelo número 13. O one-hot transforma o índice num vetor de 27 posições, todas zero menos a posição do caractere.

Detalhe que pega

one_hot devolve inteiros. O .float() é necessário para multiplicar pelos pesos, que são float.

Bloco 5 · Rede neural

Uma camada linear e a softmax

índicea letra atual13
→
one-hotvetor com um 1(1, 27)
→
@ Wlogits: "log-contagens"(1, 27)
→
.exp()vira positivo: "contagens"(1, 27)
→
÷ somaprobabilidades que somam 1(1, 27)
W = torch.randn((27, 27), generator=g, requires_grad=True)

logits = xenc @ W                           # log-contagens
counts = logits.exp()                       # equivalente a N
probs = counts / counts.sum(1, keepdims=True)
# as duas últimas linhas juntas são a 'softmax'
O truque central

Multiplicar um one-hot por W só seleciona uma linha de W. Então W é uma tabela 27 × 27, como N. A diferença é que guarda log-contagens, que podem ser negativas e são aprendidas por gradiente.

Bloco 5 · Rede neural

A mesma NLL, sem loop

loss = -probs[torch.arange(num), ys].log().mean()
loss = loss + 0.01*(W**2).mean()   # regularização

probs[torch.arange(num), ys] pega, em cada linha, a probabilidade que a rede deu para a letra certa. Depois vem a mesma receita do Bloco 4: log, negativo, média.

Indexação avançada

Dois vetores de índices do mesmo tamanho escolhem um elemento por linha: linha 0, coluna ys[0]; linha 1, coluna ys[1]; e assim por diante.

O termo 0.01*(W**2).mean() é a regularização. Ela tem um significado bonito, que fecha a aula dois slides adiante.

Bloco 5 · Rede neural

O loop de treino é o da Aula 01

for k in range(100):
    # forward
    xenc = F.one_hot(xs, num_classes=27).float()
    logits = xenc @ W
    counts = logits.exp()
    probs = counts / counts.sum(1, keepdims=True)
    loss = -probs[torch.arange(num), ys].log().mean() \
           + 0.01*(W**2).mean()

    # backward
    W.grad = None          # zerar, como na Aula 01
    loss.backward()

    # update
    W.data += -50 * W.grad

Forward, zerar, backward, passo contra o gradiente. Os mesmos quatro tempos do micrograd, agora com tensores: um backward() calcula os 729 gradientes de uma vez.

Taxa de aprendizado 50?

Parece absurdo depois do 0,1 da Aula 01, mas aqui funciona: o problema é simples e o gradiente médio é pequeno. Taxa de aprendizado não tem valor universal; é ajustada para cada problema.

W.grad = None é o "zerar" do PyTorch: mais barato que encher de zeros.

Depois de treinada, exp(W) normalizado é praticamente a tabela P da contagem. Na minha execução, a maior diferença entre as duas tabelas de probabilidade foi 0,056.

Então para que a rede?

Contar não escala. Com 3 letras de contexto já seriam 27³ ≈ 20 mil linhas, a maioria vazia. A rede generaliza com poucos parâmetros. Na parte 2, o mesmo esqueleto ganha mais contexto e uma camada escondida.

Bloco 5 · Rede neural

Regularização é a suavização da rede

O termo 0.01*(W**2).mean() pune pesos grandes e empurra W em direção a zero.

Se W fosse todo zero, todos os logits seriam iguais, as contagens seriam iguais e as probabilidades também: um modelo uniforme. É exatamente o efeito do +1 na contagem, levado ao extremo.

ContagemRedeEfeito
N + 0sem regularizaçãoajusta os dados ao máximo
N + 10.01 · W²um pouco mais suave
N + 1.000.000regularização enormepraticamente uniforme

É por isso que a NLL da rede, 2,462, fica um pouco acima do piso de 2,454: a regularização troca ajuste por suavidade.

Fechamento

A aula em seis linhas

  • Bigrama: prever a próxima letra olhando só a atual. Um . marca começo e fim.
  • Contar numa matriz 27 × 27 e normalizar as linhas já é o modelo ótimo de bigramas.
  • Gerar é sortear com multinomial, letra a letra, até sair o ponto. Semente fixa para reproduzir.
  • NLL média é a loss: log do produto vira soma, negativo para minimizar, média para comparar. Piso aqui: 2,454.
  • Zero mata a loss: suavização na contagem, regularização na rede.
  • Rede = one-hot, @ W, softmax e gradiente. Chega ao mesmo lugar, mas escala.

Responda antes de clicar

1Por que usar um único . em vez de <S> e <E>?
Nada vem antes de <S> e nada vem depois de <E>: uma linha e uma coluna ficariam sempre vazias. Um só marcador faz os dois papéis e a matriz fica 27 × 27.
2O que acontece se você esquecer o keepdims=True em P.sum(1)?
A soma vira shape (27,), o broadcasting a trata como (1, 27) e divide as colunas em vez das linhas. Não dá erro; as linhas só deixam de somar 1.
3Por que a loss é a NLL média e não o produto das probabilidades?
O produto de milhares de números menores que 1 vira zero em ponto flutuante. O log transforma o produto em soma, o negativo transforma "maximizar" em "minimizar" e a média deixa o número comparável entre conjuntos de tamanhos diferentes.
Pare e responda · 2 de 2

Responda antes de clicar

4Qual é a NLL média de um modelo que sorteia letras ao acaso? Por quê?
ln 27 ≈ 3,30. Cada caractere recebe probabilidade 1/27, e −log(1/27) = ln 27. Qualquer modelo útil tem que ficar abaixo disso.
5Por que one_hot(ix) @ W é a mesma coisa que W[ix]?
Multiplicar por um vetor com um único 1 na posição ix zera todas as linhas de W menos essa. O resultado é a linha ix.
6Por que a regularização 0.01*(W**2).mean() funciona como suavização?
Ela empurra W para zero. Com W zero, todos os logits são iguais e a distribuição é uniforme, que é para onde o +1 (ou um número maior) empurra o modelo de contagem.
