Bloco 2 · torch.nn

Embedding, Flatten e Sequential

class Embedding:
    def __init__(self, num_embeddings, embedding_dim):
        self.weight = torch.randn((num_embeddings, embedding_dim))
    def __call__(self, IX):
        self.out = self.weight[IX]
        return self.out

class Sequential:
    def __init__(self, layers):
        self.layers = layers
    def __call__(self, x):
        for layer in self.layers:
            x = layer(x)
        self.out = x
        return self.out
    def parameters(self):
        return [p for layer in self.layers for p in layer.parameters()]

logits = model(Xb)           # o forward inteiro
loss = F.cross_entropy(logits, Yb)

A tabela C vira uma camada Embedding, e a lista de camadas vira um Sequential. São os mesmos nomes do torch.nn, e se comportam igual.

Bloco 3 de 5

A árvore

Achatar 8 letras de uma vez numa camada só esmaga a informação cedo demais. A WaveNet junta aos poucos.

Bloco 3 · Árvore

Juntar de dois em dois, três vezes

A estrutura vem da WaveNet (van den Oord et al., DeepMind, 2016), criada para áudio. Cada nível combina dois vizinhos do nível de baixo; depois de três níveis, as 8 letras viram um único vetor.

Bloco 3 · Árvore

A árvore em código

class FlattenConsecutive:
    def __init__(self, n):
        self.n = n
    def __call__(self, x):
        B, T, C = x.shape
        x = x.view(B, T//self.n, C*self.n)   # junta n vizinhos
        if x.shape[1] == 1:
            x = x.squeeze(1)
        self.out = x
        return self.out

model = Sequential([
  Embedding(vocab_size, n_embd),
  FlattenConsecutive(2), Linear(n_embd*2, n_hidden, bias=False),
      BatchNorm1d(n_hidden), Tanh(),
  FlattenConsecutive(2), Linear(n_hidden*2, n_hidden, bias=False),
      BatchNorm1d(n_hidden), Tanh(),
  FlattenConsecutive(2), Linear(n_hidden*2, n_hidden, bias=False),
      BatchNorm1d(n_hidden), Tanh(),
  Linear(n_hidden, vocab_size),
])

FlattenConsecutive(2) é um view: lê a sequência de 8 posições como 4 posições, cada uma com o dobro de canais. Nada é copiado.

O @ com tensores 3D

x @ W com x (4, 4, 48) e W (48, 128) multiplica só a última dimensão. As outras viram "lote": a mesma camada é aplicada em cada uma das 4 posições.

Bloco 4 de 5

O bug da BatchNorm

O modelo hierárquico treinou e deu resultado razoável. Mesmo assim, havia um bug.

Bloco 4 · O bug

Média no eixo errado, sem erro nenhum

# x: (32, 4, 128) -- batch, posição, canal
xmean = x.mean(0, keepdim=True)   # (1, 4, 128)  errado
xmean = x.mean((0, 1), keepdim=True)  # (1, 1, 128)  certo

# correção na BatchNorm1d:
if x.ndim == 2:
    dim = 0
elif x.ndim == 3:
    dim = (0, 1)

Com média só no eixo 0, a camada mantém estatísticas separadas para cada uma das 4 posições: 4 × 128 médias, cada uma estimada com só 32 números.

Por que ninguém percebe

O broadcasting faz tudo funcionar com os shapes errados. O código roda, a loss cai e nada avisa. O único sinal é olhar o shape de running_mean: deveria ser (1, 1, 128).

Convolução é um loop eficiente

Uma convolução aplica a mesma camada linear deslizando ao longo da sequência, reaproveitando as contas compartilhadas. É a parte que o notebook deixa para a próxima aula, e a ponte para os modelos que olham sequências inteiras, como o GPT.
